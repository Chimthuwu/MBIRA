## 1. What this project IS (architecture, verified by code read)

**Goal**: a faithful mbira dzavadzimu / nyunga nyunga virtual instrument.
Windows-first (Ableton Live is the target DAW), physical model first.

**Engine (src/dsp/index.js, 502 lines — the shipped DSP)**
- Pure JS graph built on Elementary (`el.*`), executed by QuickJS (choc
  wrapper). Exposed API `globalThis.__mbira` (:498): noteOn/noteOff/sustain/
  setParam/setModeGain/setRatioSet/setTineOverride/allNotesDamp/
  configureSampleRate/configurePool/loadInstrument/getInstrument.
- 3-mode additive tine synth: per-voice 3 sine modes (cantilever ratios
  [1.0, 6.27, 17.55], physics-derived, unmeasured), exponential decay envs,
  velocity→amp+brightness, deterministic per-note jitter (hash01), signed
  pluck-position weighting + energy normalisation (L-1 fix at cea9d24).
- Shared body chain (spec 4.5 compliant: ONE shared instance): soundboard =
  5 SVF bandpass resonators (:212-234), gourd = comb + bandpass (:236-244),
  buzz = amplitude-gated tanh rattle (:246-257). All PROVISIONAL params.
- Modulator framework v1 (engine internals): per-voice ADSR, shared LFO→
  master(tremolo)/→pitch, random depth, velocity depths (:76-80).
- Macros (UI-facing): resonance/buzz/brightness scale the body chain (:227,
  :239, :247) + brightness tilts mode exponents (:135).
- Voice pool: 64 prebuilt voices notes 48–111 (:89-95), polyphony cap 64 with
  steal (oldest-released → oldest-sustained → newest-active, :297-318).
- **Every noteOn/noteOff/setParam calls renderAll()** = full graph rebuild
  (:438). Smoothed consts give ~30 ms click-free ramps; master smoothed 10 ms.
- Master gain PRE-limiter, then tanh soft limiter K=1.4, ceiling ≈0.71
  (:277-288). ← root cause of the user's P1 finding (fader ≠ loudness).

**Native host (src/native/main.cpp, 569 lines)**
- Two modes: `render` (deterministic offline WAV via the REAL elem::Runtime +
  QuickJS bundle; prints latency/CPU metrics) and `live` (RtAudio WinMM/
  DirectSound 4-buffer, RtMidi port 0, service thread runs JS; audio callback
  only calls runtime.process — threading model per docs/architecture-decision).
- Instrument JSON loaded from `MBIRA_INSTRUMENT` env (N-6 fallback fixed,
  validate-before-clear), geometry envelope posted to the webview on ui.ready.
- Legacy Win32 GDI panel (ui.h) still available via `--ui webview` toggle.

**WebView2 UI (webview_ui.h 462 lines + ui/)**
- Host → UI: `telemetry` (30 Hz peaks), `note.state` (MIDI tine lighting),
  `status` (midi ok/voices), `instrument` (geometry envelope).
- UI → host: `param.set` (allow-list `dspAccepts`, 19 params), `note.on/off`,
  `panic`, `ui.ready`. Throttled faders (~40 ms). Unknown params logged
  provisional, silently UI-only (RECOVERY-AUDIT 7.2 behaviour — by design).
- ui/ ships from disk at runtime (no rebuild needed for UI edits).

**VST3 (src/vst3/, Milestone-1 "spike" quality)**
- Minimal Steinberg plugin: stereo out, event in, NO parameters, NO state
  (kNotImplemented), NO editor. Same Engine + EventBridge pattern. Embedded
  dsp-bundle. Validator 47/47 + SmokeHost pass; MBIRA.vst3 built under
  MBIRA-M1test/. Not Ableton-verified (checklist never executed).

**Tests (3 files, 138 lines)**: instrument JSON schema validation, DSP sanity
render, native-seq repro. See §4 gaps.

## 4. Test gaps (the audit's most important finding)

The test suite does NOT exercise the shipped DSP: both dsp tests use the WASM
OfflineRenderer with a hardcoded toy graph ([1.0,2.6,4.2] ratios) and never
import build/dsp-bundle.js. Consequences: every determinism/provenance claim
rests on manual `mbira-poc render` runs; no regression guard on L-1/L-2;
no macro/param integration test; no native-path test in CI; tests/native has 8
unwired scratch files. **First-order fix: make a test that loads the REAL
bundle through the real path** (render a canonical event file, hash-compare
against a checked-in reference WAV manifest with SHA-256).

Evidence chain state: wav-m2 7/17 reproducible byte-identical, 7 permanently
unreproducible (N-1, pre-a7051f8); wav-listen (13 files) provenance asserted
but NO SHA-256 column — one uncommitted DSP edit would silently break it;
manual-test-results.md Parts A–D still blank (header also stale vs re-render
2); VST3 host checklist 0/17 executed, stale scope.

## 5. Contradictions to resolve (decision list for the human)

1. **FX row in the UI** (reverb/delay/drive/spatial): invented, no DSP, no
   spec support (§5.3 has no effects). Recommend: hide, don't fake.
2. **mode1/2/3 partial-mix knobs**: no DSP param. Either implement (cheap) or
   hide. Recommend: implement mode gains properly (they map to existing
   computeGains mode weights) or hide.
3. **Engine blend / Samples page**: spec §8 says hybrid engine is
   documentation-only; UI ships blend slider + samples page. Recommend: hide
   until the collaborator recordings exist AND the human approves.
4. **Identity lock vs modulator framework**: lock says no mod matrix UI, ever;
   how-to-run.md contradicts itself (lines 99 vs 107). Params stay engine
   internals; mod strips are the eventual surface. Resolve the doc drift.
5. **Parameter namespace drift** (spec §5.3 names vs shipped names) and
   **defaults drift** (soundboard 0.5→0.35, pluck 0.5→0.30, gourd off→0.30,
   buzz 0.2→0.0→0.2): reconcile spec §5.3 with the shipped set or amend.
6. **Missing §8 docs**: README.md, architecture.md, recording-brief.md,
   future-hybrid-engine.md, root HANDOFF.md — 5 of 6 required docs absent.
